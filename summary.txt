# AntiFine Framework Summary

## What is AntiFine?
AntiFine is a modular, automated defensive security and compliance auditing framework written in Python. It scans infrastructure and web targets, records the findings, and generates human-readable compliance reports enriched with remediation guidance. 

## Core Components:

1. Central Orchestrator (src/main.py)
The command-line interface that drives the entire framework. It uses argparse to route commands to initialize the database (--init), run various scanners (--audit-local, --audit-web), and generate reports (--report).

2. Storage Layer (src/database/setup.py)
A local SQLite database (antifine.db) that serves as the single source of truth for the audits. It uses a decoupled architecture with two primary tables:
* audit_targets: Tracks the targets being scanned (IPs, hostnames).
* scan_results: Logs the discovered vulnerabilities along with their severity and status. Scanners write to this, and the reporting engine reads from it.

3. Auditing Scanners (src/scanners/)
The active reconnaissance modules that hunt for vulnerabilities:
* Baseline Audit (baseline_audit.py): Scans for open ports and flags insecure, plaintext, or legacy services (e.g., Telnet, FTP, unencrypted databases) exposed on external interfaces.
* SSRF Web Scanner (ssrf_scanner.py): A specialized scanner that audits a given URL and its query parameters to identify Server-Side Request Forgery (SSRF) vulnerabilities.

4. Compliance Reporting Engine (src/reporting/generate.py)
An automated report generator that queries the local database and compiles a structured Markdown file (compliance_report.md). It:
* Buckets findings hierarchically by severity (CRITICAL, HIGH, MEDIUM, LOW).
* Provides static, port-specific fallback remediation advice for common misconfigurations.


4. Infrastructure-as-Code (IaC) Auditor (src/scanners/iac_audit.py)
* Added via the --audit-iac flag.
* Performs static analysis on local configuration files (like Dockerfiles and Kubernetes YAML).
* Identifies missing USER directives, missing HEALTHCHECK instructions, privileged containers, and missing resource limits.

5. Offline Knowledge Base (src/reporting/knowledge_base.py)
A local, offline dictionary mapping vulnerability types to structured technical remediation guidance. It provides a technical summary, step-by-step mitigation guidance, and secure code/configuration examples, injected directly into compliance reports.

6. SARIF JSON Exporter (src/reporting/sarif_exporter.py)
Allows the reporting engine to serialize audit findings into the SARIF 2.1.0 JSON format for native integration into CI/CD pipelines and enterprise SOC dashboards.

7. GitHub Actions Integration (.github/workflows/security.yml)
A CI/CD pipeline that automatically runs AntiFine on every push and pull request to the main branch. It initializes the database, exports findings to SARIF, and uploads them to the GitHub Security tab using the codeql-action.

## Testing & Quality Assurance:
* A robust test suite (tests/test_baseline.py, test_integration.py, test_ssrf.py) using pytest to validate core logic.
* Strict version control guidelines documented in CLAUDE.md to prevent local configuration or database states from polluting the central repository.
